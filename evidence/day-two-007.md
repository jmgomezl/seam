# Day-two usability checkpoint 007

## Implemented

The default screen is now a user-entered payment-boundary check, not a canned example gallery. Enter a public/synthetic JSON sample and JSON Pointer, then declare each side's wire units per major unit and currency. Inputs stay in memory, are not persisted in browser storage, and have no connection to the AI review route. Optional contract notes are recorded as unverified text, not fetched URLs.

The result shows concrete intended/receiver money, known declaration conflicts even for zero, missing evidence, and a separate value-1 witness for a zero mismatch. A hypothetical receiver-alignment preview preserves the original and never claims to change application code. Its test file is separately named and marked as a proposal. Editing an input invalidates the previous result immediately; Reset restores the synthetic example.

Exports include evidence JSON or a runnable Node module. The module tests the original captured payload by default, accepts another sanitized JSON response file using the same declared contracts and field pointer, and exposes checkPayload for import into a test suite. Nonzero exits are expected for disagreement or invalid data. This is a declared-boundary contract check, not automatic repository analysis or live API testing.

Example cards have descriptive topic names. Unconfigured AI is disabled rather than a clickable error path. The prior 006 unknown-route rejection, independent cloud consent and strict ONLY_ON_DEVICE/ONLY_IN_CLOUD modes remain unchanged.

## Verification and constraints

Current tests cover valid/invalid JSON, JSON Pointer escaping/root/arrays and prototype-property exclusion, finite/safe numeric values, scale validation, currencies, unknown semantics, zero, non-mutating preview, export provenance, and actual subprocess execution/import of exported tests. Browser QA was separate from this implementation-stage unit-test run. Passing unit tests is not a browser/network/inference claim.

This chapter uses JavaScript numeric arithmetic, not exact settlement arithmetic. No source discovery, provider contract inference, real integrations, measured user time savings, Firebase inference or App Check enforcement is established. No private or business data was used. No publication or submission occurred at this checkpoint.

## Review corrections and genuine Claude contribution

A separate review supplied Claude with a synthetic textual description of this flow. The critique was recorded separately; it is not part of this source import. Claude did not inspect this UI or execute the app. It called the current comparison close to a units calculator and suggested centering reusable checks, a field picker, scoped results and a test trust path. That is opinion based on the description, not user research.

Applied: numeric-field picker (up to 100 fields, 20 levels); optional notes collapsed; direct declaration-only warning on results; actionable missing-contract instructions; generated-code preview and precise assertion summary; top run button and focus/scroll to result/error. Aligned inputs no longer offer a misleading fix preview. Tiny nonzero amounts use a numeric fallback rather than rendering as zero. The independent reviewer found an export bug for JSON keys named __proto__; the embedded fallback is now parsed as JSON instead of emitted as an object literal. Actual root/nested __proto__ export execution tests pass.

58 tests now pass, including 006 privacy tests, exported-script execution and field-picker tests. Claude's suggested good/bad-response demonstration does not yet describe this product: the artifact asserts fixed declarations. Changing a response number cannot resolve mismatched units. The UI states that explicitly. A stronger future artifact would check actual adapter/receiver output against independent transaction intent; that has not been built or validated here.
