# Human-reviewed proposal to local formatter execution

After an accepted, quoted proposal and deliberate human re-entry, a separate applicability confirmation can export an external-adapter-only runner. The producer declaration must match a supported independent display oracle; both currencies must agree. The consumer scale never sets expected results. Unsupported combinations retain the declaration-only export.

The runner accepts only `--adapter ./trusted-adapter.mjs`. It imports and calls the user's synchronous `formatAmount(amount,currency)` or default export with four fixed cases for the chosen currency. The test oracle is independently authored in `lab.ts`, not generated by the model or adapted to make the implementation pass. No default/bundled correction masks an unconnected adapter.

The result JSON distinguishes human declarations, independent expected values and actual observed numeric outputs. Exit 0 means four fixed numeric display probes passed; exit 1 means an observed mismatch/error; exit 2 means setup failed. It does not validate currency symbols, payment operations, APIs or production safety. JSON contains no excerpts, model prose, paths, raw formatter strings or exception messages. Imported code can itself log arbitrary data or perform effects; this is not a sandbox and a blocking module needs an external process timeout. Shell redirection should use a new report filename; the runner does not manage files.

Validation: required adapter, incorrect arguments, correct/wrong actual external adapters, thrown formatter, missing export, independent expectation despite consumer-scale mismatch, unsupported oracle, separate applicability confirmation. Full tests and build pass. Live Firebase extraction and browser export completion remain unverified; this change does not configure Firebase or claim that a real customer adapter has been tested.
